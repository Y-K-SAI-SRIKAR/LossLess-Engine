  # LossLess Engine : Frontend

  User-facing React application for fraud-risk detection and analysis. Provides transaction evaluation workflows, result visualization, model inspection, and feedback collection integrated with backend fraud-detection services.

  ---

  ## Overview

  The LossLess Engine Frontend is the presentation layer of a complete fraud-detection platform. It does **not perform fraud classification itself**; instead, it provides the interactive interface through which users submit transactions, execute analysis workflows, review risk decisions, and provide feedback.

  The fraud intelligence is generated by the downstream Backend, Agent, and ML services. The frontend's responsibility is to make that intelligence accessible, understandable, and actionable for human decision-makers.

  ## Core Features

  ### Single Transaction Analysis

  Users submit individual transactions for fraud-risk assessment:

  1. User uploads CSV with transaction data
  2. Frontend validates file and submits to backend
  3. Backend coordinates Agent and ML services
  4. Result presented with:
    - Risk level (LOW / MEDIUM / HIGH)
    - Recommended action (APPROVE / REVIEW / BLOCK)
    - Fraud probability (in human-readable percentage)
    - Evidence summary (behavioral patterns, velocity, anomalies)
    - Model metadata (version, threshold, feature importance)

  **Key insight:** The frontend deliberately abstracts raw ML probabilities into business-ready risk interpretations.

  ### Batch Transaction Analysis

  Process multiple transactions in a single workflow:

  1. User uploads CSV with multiple transactions
  2. Frontend initiates batch job
  3. Backend processes transactions in parallel
  4. Results aggregated and reported:
    - Total transaction count
    - Fraud count and fraud rate
    - Per-transaction decisions
    - Downloadable report from S3

  ### Result Presentation

  Results are extracted from nested Agent responses and presented clearly:

  ```json
  // Agent returns complex nested structure
  {
    "prediction_tool": {
      "fraud_probability": 0.064
    },
    "decision_tool": {
      "risk_level": "LOW",
      "action": "APPROVE"
    },
    "explanation": "..."
  }

  // Frontend extracts and presents
  Risk Level: LOW
  Action: APPROVE
  Fraud Probability: 6.4%
  ```

  The frontend does **not expose raw JSON** to users. Instead, it translates backend responses into human-understandable decisions.

  ### Model Information & Benchmarking

  Users can inspect:
  - Model version and alias
  - Production decision threshold
  - Feature importance rankings
  - Performance metrics (ROC-AUC, precision, recall)
  - Comparison visualizations

  ### Feedback Collection

  Post-analysis feedback submission enables model improvement:
  - Users provide actual fraud outcome
  - Frontend persists feedback to backend
  - Feedback collected for model retraining

  ## Security Principles

  1. **Never Store Secrets in Frontend Code**
    - Database credentials never stored
    - AWS credentials never exposed
    - Backend infrastructure hidden behind application layer
    - Only user-facing functionality visible

  2. **Backend Controls Security Boundary**
    - CORS configured and enforced by backend
    - Frontend cannot bypass backend validation
    - All sensitive operations server-side

  3. **Data Minimization**
    - Frontend only receives information necessary for presentation
    - Transaction PII handled by backend, not frontend
    - Analysis results processed for display, not storage

  ---

  ## Design Principles

  1. **Component Reusability** : UI components decoupled from page-level logic
  2. **Separation of Concerns** : API communication, state management, presentation isolated
  3. **Clear User Feedback** : Loading states, error messages, success confirmation
  4. **Minimal Backend Exposure** : Users see risk decisions, not infrastructure details
  5. **Responsive Interaction** : Graceful loading and error states
  6. **Environment-Based Config** : Same code runs in dev and production
  7. **No Fraud Logic in Frontend** : Prevents inconsistency with production model
  8. **Accessible Results** : Percentages instead of raw probabilities; risk levels instead of scores

  ## Common Issues

  **Backend URL Misconfigured**
  - Check `VITE_BACKEND_URL` in `.env` or Vercel environment
  - Verify backend service is running and accessible
  - Check CORS origin is whitelisted in backend

  **File Upload Fails**
  - Verify CSV format matches expected schema
  - Check file size limits (backend may have limits)
  - Ensure backend multipart handling is enabled

  **Results Not Displaying**
  - Frontend searches nested Agent responses — check response structure
  - Open browser DevTools to inspect backend response
  - Verify all required fields present in analysis response
